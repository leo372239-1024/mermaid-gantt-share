# iPhone 强提醒配置指南（快捷指令 · 零服务器）

> 目标：让「甘特图里临近截止的待办」在 iPhone 上以**系统级闹钟强度**提醒你——
> 突破静音开关、突破专注模式，铃声持续到你手动停掉。
>
> 为什么不用第三方 App：iOS 的推送分五档，最强的「系统级闹钟」和「关键警报」都拿不到
> 网页/普通开发者的权限（关键警报需要 Apple 单独审批）。而 iOS 自带的「快捷指令」可以直接
> 调用系统计时器，**不需要服务器、不需要装任何 App、不需要 Apple 开发者账号**。
>
> 📌 **本文是「到点强提醒」这一条路线。** 如果你要的是**写进系统日历/时钟 App 的原生提醒**
> （订阅一次长期生效、静音也能响的真闹钟），请直接看
> [`ios-system-alarm-setup.md`](./ios-system-alarm-setup.md)。两套方案互不冲突，可以叠加使用。

---

## 一、整体链路

```
gantt.md  ──(GitHub Actions 编译)──┬─▶  deadlines.json  ──(HTTPS)──▶  iPhone 快捷指令
                                   │                                    │
                                   │              遍历 → 筛出 24h 内到期 → 计时器响铃
                                   └─▶  deadlines.ics   ──(日历订阅)──▶  系统日历闹铃（见另一份文档）
```

- `deadlines.json` / `deadlines.ics` 由 `tools/build-deadlines.js` 从 `gantt.md` + `js/events.js`
  自动生成，**不要手工编辑**。线上地址：

  ```
  https://leo372239-1024.github.io/mermaid-gantt-share/deadlines.json
  https://leo372239-1024.github.io/mermaid-gantt-share/deadlines.ics
  ```

- 快捷指令在本地做筛选，判断依据用 `daysLeft`（距**截止**的自然日天数，同一天内恒定），
  不要用 `hoursLeft`（那是生成时刻的快照，几小时后会失真）。
  若要**创建系统闹钟**，筛选依据改用 `startDaysLeft`（距**开始**的自然日天数），
  因为闹钟锚在开始时刻而不是截止时刻。

### 常用字段（每条 item）

| 字段 | 含义 | 示例 |
|---|---|---|
| `id` / `name` | 任务 id / 展示名 | `t25` / `文艺汇演领票` |
| `startAt` / `startTime` | **开始**的绝对时刻 / 时分（取自日期组件） | `2026-09-10T06:00:00.000Z` / `14:00` |
| `dueAt` / `time` | **截止**的绝对时刻 / 时分（精确到分钟） | `2026-09-10T09:00:00.000Z` / `17:00` |
| `window` | 分钟级起止文案，可直接当通知正文 | `9.10 14:00 → 9.10 17:00` |
| `daysLeft` | 距截止的自然日数（0=今天，负=已过期） | `0` |
| `startDaysLeft` | 距**开始日**的自然日数（创建闹钟请用这个） | `0` |
| `startExact` / `dueExact` | 该时刻是显式填写的还是推定值 | `true` / `false` |
| `alarmAt` / `alarmTime` | 系统闹钟的绝对时刻 / "时:分"（= 开始前 15 分钟） | `2026-09-10T05:45:00.000Z` / `13:45` |
| `alarmLabel` | 系统闹钟的标签（名称 + 起止日期时间） | `文艺汇演领票 9.10 14:00 → 9.10 17:00` |
| `alarmLead` / `alarmExact` | 提前量（分钟）/ 该条能否建闹钟 | `15` / `true` |
| `alert` / `detail` / `owner` / `where` | 一句话提醒 / 长文案 / 负责班委 / 地点 | — |

> `dueExact: false` 表示甘特图里没填「时刻」，截止按**当日 23:59** 计。
> 想让它精确到分钟，就在编辑表单的「时刻」里填上。

| 项 | 要求 |

| 自带 App | 「快捷指令」（Shortcuts），系统预装，若删过请到 App Store 重装 |

## 三、Part 1：创建快捷指令

打开「快捷指令」→ 底部切到「**快捷指令**」标签 → 右上角 **＋** → 新建空白快捷指令。

按顺序添加以下动作（动作名取自中文版 iOS，不同系统版本措辞可能略有差异）：

| # | 动作 | 参数设置 |
|---|---|---|
| 1 | **获取 URL 内容** | URL 填 `https://leo372239-1024.github.io/mermaid-gantt-share/deadlines.json`；方法 `GET`。展开箭头里把「请求头」留空即可 |
| 2 | **获取字典的值** | 获取 **[URL 内容]** 中的 **[items]**（键名直接手输 `items`） |
| 3 | **设定变量** | 变量名 `命中`，值设为**空文本**（先放一个「文本」动作，内容留空，再引用它） |
| 4 | **对每个项目重复** | 重复对象选 **[字典值]**（即上一步的 items 数组） |
| 5 | **获取字典的值** | 获取 **[重复项目]** 中的 **[daysLeft]** |
| 6 | **如果** | 条件：**[字典值]** `小于或等于` `1` |
| 7 | **添加到变量** | 把 **[重复项目]** 的 **[name]** 与 **[window]** 拼成一行（用「文本」动作拼：`[name] —— [window]`），添加到变量 `命中` |
| 8 | **结束如果** | 关闭第 6 步的块 |
| 9 | **结束重复** | 关闭第 4 步的块 |
| 10 | **如果** | 条件：变量 `命中` `有任何值` |
| 11 | **合并文本** | 把 `命中` 用**换行**连接（分隔符选「换行」），得到一个多行字符串 |
| 12 | **开始计时器** | 时长 **1 秒** |
| 13 | **显示通知** | 标题：`甘特图待办提醒`；正文：**[合并后的文本]** |
| 14 | **结束如果** | 关闭第 10 步的块 |

> **为什么是「1 秒计时器」**：快捷指令的「显示通知」会被静音开关压制，但**系统计时器到点会强制响铃**，
> 行为等同闹钟——能穿透静音与专注模式。用 1 秒是为了让它立刻响，而不是真的计时。
>
> 第 12、13 步的先后顺序无所谓，但**计时器必须放在循环外**：计时器全局只有一个，
> 放在循环里会被反复重置，最终只响最后一次。

完成后点右上角命名，建议叫 **「查甘特图待办」**。

## 四、Part 2：创建定时自动化

1. 「快捷指令」→ 底部切到「**自动化**」标签 → **＋**（或「新建自动化」）；
2. 触发条件选「**特定时间**」：
   - 时间：`20:00`（建议晚上，方便第二天带材料）
   - 重复：`每天`
3. 下一步 → 选择「**运行快捷指令**」→ 选刚建的「查甘特图待办」；
4. **关键开关**：把「**运行前询问**」关掉（选「立即运行」）。开着的话每次都会弹确认框，提醒就废了；
5. 「运行时通知」建议**保持开启**，这样你能在通知中心看到自动化确实执行过；
6. 完成。

建议再建一条 **08:00** 的自动化，指向同一个快捷指令，覆盖早上的场景。
同一天两次提醒内容相同是正常的——它提醒的是"还有哪些没做"，不是"有新消息"。

## 五、Part 3：验证

1. 在「快捷指令」里**手动点一下**「查甘特图待办」运行它；
2. 首次运行 iOS 会询问是否允许访问该网址 → 选「允许」；
3. 若窗口内有 24h 内到期项，应该立刻听到计时器响铃 + 收到一条通知；
4. 若没有到期项，则应当**静默无输出**（这是正确行为，不是故障）。

想强制测试响铃效果：把第 6 步的条件临时改成 `小于或等于 30`，手动跑一次，验证后再改回 `1`。

## 六、调整提醒提前量

第 6 步的阈值就是"提前几天提醒"：

| 阈值 | 效果 |
|---|---|
| `0` | 仅到期当天提醒（最安静） |
| `1` | 到期当天 + 前一天提醒（**推荐**） |
| `3` | 提前三天开始，每天提醒，直到过期后 1 天 |
| `7` | 提前一周开始，适合需要准备材料的任务 |

`daysLeft` 为负数表示已过期。脚本默认在过期后仍保留 1 天（宽限期），
方便你发现"漏标 `done`"的任务——看到这类提醒就去 `gantt.md` 把对应任务标成 `done`。

## 七、进阶变体

**A. 换成真闹钟（响得更久，但会累积）**
把第 12 步的「开始计时器」换成「**创建闹钟**」，时间设为当前时间 + 1 分钟。
系统闹钟会一直响到你手动关闭，强度比计时器更高。代价是每次运行都会在「时钟」App 里
留下一条闹钟记录，需要定期清理。

> ⚠️ 这里有一个必须知道的坑：**时钟 App 的闹钟只有「时刻 + 重复」，不能绑定具体日期**。
> 给"明天 09:00 开始"的待办设 08:45 闹钟，它会在**今天** 08:45 就响。
> 因此真闹钟只对**当天开始**的待办有意义——完整做法（按 `startDaysLeft = 0` 过滤、
> 闹钟时间取 `alarmAt` = **开始前 15 分钟**、标签取 `alarmLabel` = **名称 + 起止日期时间**、
> 一键从网页唤起、每天自动同步）见
> [`ios-system-alarm-setup.md`](./ios-system-alarm-setup.md) 的通道 C。

**B. 加一个主屏徽标**
在第 2 步之后插入「**获取字典的值**」取 `within24h`，再配合「**设置徽标数字**」
（需要配合支持徽标的 App 或小组件）。快捷指令本身在主屏无法显示徽标，
如需徽标建议改用「提醒事项」App 承载。

**C. 把待办直接写进系统「提醒事项」**
把第 12 步替换为「**添加新提醒事项**」，正文用 `alert`。好处是进了系统提醒事项后可
统一管理、可打勾；缺点是提醒强度回落为普通通知，**不再有强提醒效果**。
若你的 iPhone 是 iOS 26.2+，「提醒事项」新建提醒时会出现「**紧急**」开关，
打开后可直接把待办升级为系统闹钟级提醒——这是目前最理想的组合，但需要在手机上手动逐条开启。

## 八、常见问题

**Q：到点没响？**
按顺序排查：①「运行前询问」是否已关闭；②手机是否处于关机状态（关机不执行自动化，
低电量模式不影响）；③手动运行一次看是否报错；④检查 `deadlines.json` 是否已上线
（浏览器打开该 URL 应看到 JSON）。

**Q：计时器铃声太小 / 被音乐盖住？**
计时器铃声在「时钟」App → 底部「计时器」标签 → 「计时结束时启用」里设置。
另外计时器会接管当前音频播放，这是系统行为，无法绕开。

**Q：能不能让全班同学都收到？**
可以，但每个人的手机都要各自建一次这个快捷指令——快捷指令无法远程分发到别人手机上。
如果能接受"装一个 App"，替代方案是 GitHub Actions 定时调用 Bark 推送
（支持 `level=critical` 突破静音的**关键警报**，且 `call=1` 可让铃声循环 30 秒），
缺点是每位同学都要安装 Bark、在 App 内单独授权「重要警告」，并把 device key 汇总给你。

**Q：数据多久更新一次？**
`gantt.md` 每次 push 后 GitHub Actions 会自动重建 `deadlines.json` 与 `deadlines.ics`；
此外每天 06:00 和 18:00（北京时间）各定时重建一次，用于刷新 `daysLeft` 这类相对字段。

**Q：截止时间是精确到分钟的吗？**
是。`time` / `dueAt` 取自编辑表单里「结束日期 + 时刻」两个组件，例如「文艺汇演领票」
的截止是 `17:00`（`dueAt = 2026-09-10T09:00:00.000Z`）。若某项没填「时刻」，
则按当日 `23:59` 计，并把 `dueExact` 标为 `false` 供你判断。

**Q：为什么第 1 步的 URL 是 `deadlines.json` 而不是 `gantt.md`？**
`gantt.md` 是 Mermaid 语法，快捷指令解析它需要处理 section 层级、状态词、
以及日期里混排的冒号（如 `14:30`），极易出错。`deadlines.json` 是已经拍平的结构化数据，
快捷指令只需几次「取字典值」即可，稳定得多。
